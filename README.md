# CRM для агенції нерухомості

Односторінковий фронтенд (`crm.html`) + Node.js/Express бекенд (`server/`) на PostgreSQL.
Ліди, воронка продажів, задачі/нагадування, каталог обʼєктів, Telegram-бот,
аналітика — все в одному проєкті, без зовнішніх сервісів (окрім самого Postgres
і, опційно, Telegram + Anthropic API для AI-функцій).

## Швидкий старт (найпростіше — Railway)

1. Створіть акаунт на [railway.app](https://railway.app), новий проєкт.
2. Додайте плагін **PostgreSQL** (Railway сам створить `DATABASE_URL`).
3. Додайте цей код як другий сервіс (Deploy from GitHub repo, або
   `railway up` з цієї теки через [Railway CLI](https://docs.railway.app/guides/cli)).
4. У змінних середовища сервісу задайте (див. `.env.example`):
   - `SESSION_SECRET` — будь-який довгий випадковий рядок
   - `ADMIN_USER`, `ADMIN_PASS` — логін/пароль першого адмін-акаунту
     (створюється автоматично при першому запуску на порожній базі)
   - `PUBLIC_BASE_URL` — публічний HTTPS-домен сервісу (потрібен лише для Telegram-бота)
   - `ANTHROPIC_API_KEY` — опційно, лише для AI-функцій (розпізнавання скріншотів
     переписки, оновлення карточки текстовим повідомленням у Telegram)
5. Задеплойте. При першому запуску сервер сам створить всі таблиці
   (`server/schema.sql` виконується автоматично, ідемпотентно) і адмін-акаунт.
6. Відкрийте `https://<ваш-домен>/crm.html`, увійдіть під `ADMIN_USER`/`ADMIN_PASS`.

Підійде будь-який хостинг, що вміє Node.js + дає доступ до Postgres
(Render, Fly.io, звичайний VPS тощо) — Railway не є жорсткою вимогою.

## Локальний запуск (для розробки/тестів)

```bash
npm install
cp .env.example .env
# впишіть у .env свій DATABASE_URL (можна від Railway, Supabase, локального Postgres тощо)
npm start
```

Сервер підніметься на `http://localhost:3000/crm.html` (порт з `PORT` в `.env`).

## Структура проєкту

- `crm.html` — весь фронтенд (без збірки, відкривається як є через сервер)
- `object.html` — публічна сторінка одного обʼєкта каталогу (без логіну)
- `server/index.js` — точка входу Express-сервера
- `server/schema.sql` — схема БД, застосовується автоматично при старті
- `server/routes/` — API-роути (клієнти, власники, каталог, статистика, Telegram-вебхук тощо)
- `server/clientOps.js` — спільна логіка створення/оновлення клієнта (дублі, події)
- `server/telegram.js`, `server/aiIntake.js` — інтеграція з Telegram-ботом і Claude API

## Важливо перед передачею іншій компанії

Цей архів **не містить жодних даних** попереднього власника — ані клієнтів,
ані паролів, ані API-ключів (все це в базі даних і в `.env`, які сюди не
входять). Все, що потрібно — своя порожня Postgres-база і свої значення в
`.env` — сервер сам ініціалізує чисту схему і створить новий адмін-акаунт з
нуля.
